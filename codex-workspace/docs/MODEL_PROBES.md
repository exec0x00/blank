# Explicit model configuration tests

Model tests are independent of profile saving and ordinary conversation admission. An unsaved literal model ID or custom reasoning level can be tested without a context-window declaration. An unsuccessful or untested configuration can still be added or edited. A normal conversation still requires the configured context and declared capabilities.

`POST /api/model-probes` takes one exact model ID plus optional reasoning effort, public summary, verbosity, and a separate test output budget. Omitted/null options stay omitted; literal `none` remains a real wire value. The displayed test budget defaults to 1,024 tokens and accepts 1–4,096. It does not replace or silently truncate the profile’s ordinary output budget. The UI may explicitly queue up to eight selected efforts, one request at a time.

The fixed benign probe uses the same direct owner Responses endpoint, an explicit native HTTPS agent and the server-managed placeholder. It has no tools, history, custom instructions, endpoint/key controls, redirects, discovery calls or automatic retries. Complete server-owned `HOST_RULES` are always in Responses `instructions`, separately from the fixed user input, without reading AGENTS.md.

A completed, nonempty assistant text result is required; HTTP 200 alone is insufficient. The parser supports Codex-style completed item events with terminal metadata, distinguishes rejections from access/network/rate/timeout/incomplete/refusal results, and reports the actual returned model identity. A different identity is visibly reported. One accepted request cannot prove the model honored every option, establish its context capacity, or guarantee later availability. Reasoning-summary presence refers only to public summary fields. Model text, hidden/encrypted reasoning, raw errors, usage statistics and provider protocol objects are never returned or persisted.

Each attempt is limited to 60 seconds, 512 KiB of received output, 128 KiB per event and 4,096 events. There are at most two active requests and 12 starts per rolling ten-minute window. Cancellation closes actual upstream IO; a transport that ignores cancellation retains its occupied slot, and a late response cannot overwrite a cancelled verdict. The HTTP route also rechecks session authority periodically and before delivering a result; logout and client disconnection abort admitted work.

At most 128 latest configuration results are persisted under the normal durable state directory. `GET /api/model-probes?model=exact-id` returns at most 32 results for that exact model. Each record includes the tested values, a versioned request fingerprint, timestamps and a bounded sanitized verdict. This stores no app-wide usage totals. A result-store failure is indicated by `historySaved:false` and never prevents a model from being saved or a new test from running.

Root integration: mount `createModelProbesRouter(ctx, { authorizeRequest: req => auth.authenticated(req) })` behind common authentication/origin protection, and call `closeModelProbes(ctx)` during shutdown.

Protocol references: [OpenAI Responses create reference](https://developers.openai.com/api/reference/resources/responses/methods/create), and the preserved upstream `codex-rs/codex-api/src/sse/responses.rs` plus `tests/sse_end_to_end.rs`. OpenAI’s output bound includes reasoning tokens; a small-budget test can therefore remain inconclusive at a high effort. The candidate test deliberately performs structural validation rather than pretending to know an unknown model’s capabilities.

Verification sources: `tests/model-probes-transport.test.ts`, `tests/model-probes-service.test.ts`, and `tests/model-probes-api.test.ts`. These use controlled fake provider responses and actual local HTTP/authentication and persistence. They do not contact the owner’s provider. The initial shared gate exercised 70 probe assertions successfully, but its command exited 1 because a native-to-Web cancellation race threw after assertions completed. That run is not accepted as passing. The response bridge now detaches native data delivery before destroy and guards queued callbacks; dedicated buffered-cancel, deferred-close, late-data/error and backpressure regressions were added. The coordinator’s rerun is pending.
