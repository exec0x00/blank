# Official CLI retirement plan

The 2026-09-22 migration makes the official Codex CLI authoritative for threads, turns, tools, approvals, queues, goals and history. The TypeScript server keeps authentication, the app-server bridge and site tools. Old conversations stay read-only; old queues, goals, hook results and model input must never be replayed as native sessions.

This is a reviewable plan, not a deletion script. No production/test bulk deletion or actual durable-data inspection has been performed. The full exact-path inventory, source hashes, incoming dependency edges and per-test decisions are in [.release-verification/cli-retirement-plan.json](../.release-verification/cli-retirement-plan.json). It records **87 candidate modules**, **14 modules held for compatibility extraction**, and **321 test files**. Recheck the recorded hashes before action: native integration is being edited concurrently.

| Area | Retirement decision |
| --- | --- |
| Custom agent loop | Retire `server/agent/engine.ts`, transport/tools/collaboration, custom goals/queue/compaction/history execution, naming and role/instruction assembly after native routes and DTOs replace their callers. |
| Models/provider/probes | Retire custom model registry, editable profiles and model probe modules. The current `server/provider.ts` is already a native status/fixed-URL adapter; keep it. Rewrite generic settings/bootstrap rather than deleting editor preferences. Keep the fixed provider/no-key/no-proxy policy in CLI configuration. |
| Custom memories | Retire extraction/consolidation/recall/notes/usage runtime and their UI/API, not stored user data. Keep legacy cleanup ownership and never import those facts implicitly into native history. |
| Custom plugins/hooks/workflows | Retire alternate execution/catalog/install and command migration. Native skills/plugins use official supported methods only. Preserve user files and native/project guidance; do not rewrite or erase them as a code-retirement step. |
| Custom review/context/web/image/file tools | Retire custom execution, review/Undo accounting and provider protocol adapters. Keep site uploads, image/file storage, generated-asset viewing/save/download and old public rendering where still used. |
| Rewind/checkpoints | Stop new custom captures and rewinds. Hold mutation/checkpoint modules until needed readers/cleanup are separated; preserve uncertain operation, CAS, Git-index and transcript backups. No automatic settlement. |

The new CLI runtime currently retains only these old-folder utilities through runtime imports: `server/agent/attachments.ts`, `server/agent/context-usage-projection.ts`, `server/agent/generated-image-reference.ts`, `server/agent/history-tool-details.ts`, `server/agent/host-policy.ts`, `server/agent/image-upload-promotion.ts`, `server/agent/image.ts`, `server/agent/public-history.ts`, `server/agent/timeline.ts`. Their folder/name does not make them an alternate agent. Keep or relocate them as small site/legacy modules. `server/agent.ts`, `server/index.ts`, `server/settings.ts`, `server/provider.ts`, `server/context.ts`, `shared/types.ts`, `ChatPanel` and `SettingsDialog` are migration entrypoints to rewrite, not blanket deletion targets. Keep storage/CAS/native rename, worktrees/activity, Git environment, host-resource/runtime-storage helpers, real PTYs, workspace/trash, authentication, GitHub, uploads/downloads and directory/editor services.

## Dependency cuts already completed in this lane

`server/legacy/rewind-barriers.ts` exports `restoreLegacyRewindBarriers(config)`. It validates bounded signed operation/block records through a pinned state directory and restores process-local workspace-family barriers. It performs no transcript/plan/backup/checkout reads, CAS repair, pruning, timer or state write. Missing markers and pending flags that disagree remain conservative. Corrupt, conflicting or changing authority fails closed; existing barriers are never cleared. The returned IDs describe blockers found by that inspection, not a claim that other in-memory barriers cannot exist.

`server/legacy/thread-tombstone.ts` publishes and verifies permanent old-thread markers using the caller's pinned cleanup I/O and real JsonStore key queue, without loading ThreadIndex. Existing ownership/signed receipts, aggregate filtering and payload deletion order remain in workspace cleanup. Valid markers stay byte-identical; malformed/conflicting markers stay preserved with an explicit failure.

`server/legacy/memory-cleanup-metadata.ts` keeps only frozen scope/author validators, artifact paths and the 86-artifact limit. This breaks `workspace-artifacts → conversation cleanup → memory cleanup → artifact-content → transport/extraction`. `server/legacy/change-limits.ts` preserves the 2 MiB agent image-save limit without importing ChangeTracker. Project extension cleanup preserves the normal change event and durable owner filtering without an obsolete execution/catalog cache.

Validation is bounded and local: 27 barrier cases and 95 distinct cleanup/image cases pass; scoped strict types pass. The first cleanup aggregate's notification failure is retained as evidence, and its missing plain event was fixed. An architectural assertion proves the four cleanup/delivery runtime closures exclude the old engine, transport, extraction, ThreadIndex, ChangeTracker and ExtensionsService. No model, network or actual user-data operations were performed.

## Tests and data protection

The machine-readable plan distinguishes tests solely asserting retired custom contracts from tests that must be ported or retained. Names such as `agent-attachments`, `native-atomic-rename` and `workspace-memory-cleanup` are not safe blanket removals. Keep image/general-file ownership and staging, auth/SSE revocation, worktree leases, host restrictions, PTY behavior, persistence, public history rendering and uncertain recovery tests. Port their custom transport/fixture assumptions to native CLI coverage. Retire custom memory/model-probe/plugin-executor/compaction/review tests because those implementations are deliberately removed, not because a failed test is inconvenient. Do not replace failures with skips or claim old fixtures prove the CLI.

Keep the original signed recovery exclusion helper before metadata restoration, the new barrier reader before any writer startup, and `assertWorkspaceFileRewindDeletionAllowed` before trash/purge. The former `initializeFileRewinds` also repaired transcript metadata and pruned state, so it is not an acceptable read-only migration initializer. Keep `file-rewind-*.json`, `file-rewinds/**`, parked CAS/original files, checkpoint blobs, thread backups/journals/tombstones, saved accounts/secrets/settings and user skills/workflows. Code retirement authorizes no data sweep. Existing explicit workspace deletion alone can use its exact ownership-checked cleanup leaves.

No absence of unresolved recovery is asserted: this lane did not inspect actual persistent user state. After the coordinator breaks the remaining edges, review exact candidate paths, remove only authorized obsolete code/tests, then perform native/site/storage/auth/type/build verification and regenerate the dependency graph.

Shared DTO extraction is completed. The scoped compatibility typechecks pass; this lane did not run or claim a whole-project native migration build. Exact source/test removal remains coordinator-owned after dependency review.
