## Remaining work and limits

Freeze the completed combined source, run required exact-source gates, synchronize verified source, publish without state cleanup and verify the matching running revision. Then complete original-session persistence and the bounded live parent/child proof. Earlier releases and focused reruns do not substitute for the final candidate.

The actual HF probe ran pinned full Chromium as UID/GID1000 with verified required libraries and failed with `No usable sandbox`. The host has a seccomp filter and lacks SYS_ADMIN in its capability bound. No security switch, kernel policy, manual namespace wrapper or container bypass was used. The user's scope choice remains pending: leave native browsing visibly unavailable on this Space, or use a compatible host explicitly supplied by the user. A read-only pinned-source audit confirmed that a configured setuid fallback was not exercised. Its required SYS_ADMIN authority is absent from the saved permitted/effective/bounding masks, so correct packaging alone is not expected to resolve this; the saved evidence omits inheritable/ambient masks and securebits, and absolute impossibility is not claimed. Browser website transfers, annotations and personal-browser extension parity are also not certified.

MCP is excluded. Unsupported realtime audio is explicitly excluded after an actual fixed-endpoint rejection; [REALTIME_CAPABILITY.md](REALTIME_CAPABILITY.md) records that decision, which is not a blocker. Preserving upstream source does not claim every desktop subsystem was ported. Normal Chromium/Playwright frontend verification remains allowed.

The absolute memory ceiling is 90,000,000,000 bytes with normally 2 GB reserved, counting cache/tmpfs. Verification samples cgroup usage and backing filesystems. Native `/data` stays authoritative; builds/caches use owned temporary directories. Credentials are excluded from source, evidence and delegated tasks.
