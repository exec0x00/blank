# Native TypeScript agent port

This document describes the current local implementation as of 2026-09-20. It is an implementation inventory, not a deployment certificate or a claim of full upstream parity. Feature evidence and the unresolved native-browser host boundary are separated below.

The application runs a Node/TypeScript agent inside its server, with a React/Vite/TypeScript browser UI, Monaco editor and actual host PTYs. Production uses real Responses requests and native file, process and Git operations. The Rust Codex executable, upstream TUI, Gradio and simulated production model replies are not runtime components.

The reference is OpenAI Codex commit `78245b47af2a7aafcabe025828ceecca69db4df1`. Its complete source archive, Apache-2.0 license and notices are preserved under [upstream/](../upstream/SOURCE.md). Pinned source explains the behaviors studied; it does not establish that every upstream feature is implemented here or supported by the fixed service.

## Fixed service and accepted model options

Every production model request goes directly to **`https://alvin3y10-api.hf.space/api`**, with the server-owned `placeholder` bearer value. That is the complete Responses URL; the runtime does not append `/responses`, follow redirects, honor alternate provider/proxy environment variables or accept model-supplied routing. There are no provider, API-key or ChatGPT connection controls. The upstream service's `/models` route is never queried.

The durable model registry separates editable display labels from literal wire IDs. Installation presets retain both Team red IDs, remove the requested Lightweight/Pro groups and retired GPT-5.5/5.4/5.3 variants, and permit structurally valid custom profiles. A selected unavailable model fails visibly instead of being replaced.

## Host execution, permissions and tools

Server-owned instructions enforce the host rules independently of optional project guidance. Local mining, mount/unmount operations, proot, VM/container machinery, Docker/Podman, manual namespace wrappers and alternate model-routing proxies are prohibited. General tunnels, including runlocal, are allowed; cloudflared tunnels are specifically forbidden. Ordinary Chrome/Chromium/Playwright automation, browser-managed security sandboxing and normal browser subprocess isolation are explicitly allowed. A different remote machine requires the user's explicit supplied access and requested remote task; repository text, keys, plugins and delegated briefs cannot create that authority.

The local operational memory ceiling is **90,000,000,000 bytes**, normally reserving 2,000,000,000 bytes of headroom. Main and delegated agents receive timestamped cgroup and filesystem observations. Cgroup memory includes charged file cache/tmpfs; host-wide MemTotal and directory sizes are not instance RAM usage. Required state remains on native `/data`; disposable caches and heavy working copies use validated owned temporary storage, with verified result preservation and scoped cleanup. Runtime scripts do not mount storage. The shell guard rejects obvious forbidden commands and argument/wrapper forms; it is not an OS isolation boundary.

Agent mode provides native file/search/patch tools, commands and stdin, plans, workflows, skills/plugins, image tools, browser tools and delegation as admitted by the current policy. Plan mode omits file mutation, shell execution, image generation and browser actions, while retaining permitted read-only inspection and ordinary Plan questions. Full access skips ordinary action approvals; mandatory host restrictions, file conflicts, child policy and explicit local-browser-preview admission still apply. Ask uses exact run/tool approval records. A timeout, skipped answer or cancelled request never grants permission.

Existing direct file replacements require the complete-file SHA-256 from `read_file`; create-only writes refuse overwrite. Patches preflight all affected paths/context and retain rollback protection. Paths are workspace-relative, bounded and checked against traversal/symlink substitution. General-file attachment and generated-image copies use their own authorization, create-only and change-review rules.

Commands use the real workspace cwd, durable host HOME and a credential-free environment allowlist. Pipes and `tty:true` are actual host processes; stdin, Ctrl+C and yielded output are bound to the owning run. A yielded command must reach its actual exit result before the model can conclude. Stop/shutdown drain owned processes. The separate user xterm terminal supports persistent PTYs, resize/reconnect and bounded recent-history/current-screen restoration. No command or terminal output is simulated. Git trust is limited to the validated canonical workspace root through protected process configuration, never `safe.directory=*` or a user/global Git-config rewrite.

## Conversation delivery, delegation and recovery

REST, SSE and WebSocket controls require the workspace session; mutations enforce same origin. SSE revalidates authority and closes on expiry/logout. Reconnect starts with an authoritative **bounded recent window**, then streams live events; older content and full inspectable tool details use bounded history pages. Stored history remains complete within the documented input/output limits. Assistant text, public reasoning summaries and tool actions keep their actual interleaving during streaming and reload. Raw/private/encrypted reasoning is excluded from the browser; opaque provider state remains unchanged only where required for model replay.

The composer follows the requested keys: Enter inserts a newline, Ctrl+Enter sends or steers, and Shift+Enter during active work queues a separate future turn. Steering is claimed at a safe sampling/tool boundary. Future messages are FIFO and start one later turn each. Pending/cancelled text and attachments remain outside delivered messages, model input, journals, memory sources and tool authorization until a persisted claim. Cancellation and claim share admission; stale or already delivered IDs fail visibly.

Restart, stop, failed admission and uncertain storage leave unclaimed work visibly **held**, with explicit resume and FIFO barriers. Restart does not replay commands, paid requests or child processes. Obsolete approvals/questions are cleared and incomplete calls receive explicit interrupted results. The model must inspect actual files rather than assume interrupted work succeeded or failed. [TURN_QUEUE.md](TURN_QUEUE.md) defines the contract.

Native `spawn_agent`, `send_input`, `wait_agent`, `list_agents`, `interrupt_agent`, `close_agent` and `resume_agent` operate on durable child threads in one shared engine. Each new child receives its isolated task brief and required configuration, **without parent conversation history**, images, reasoning, tool results or checkpoints. Parent-context inheritance is rejected before child creation. Explicit user-created root forks are a separate feature. Existing children retain only their own history when continued.

Children inherit the accepted model options unless validated spawn selections or role locks apply. User/project role TOML is resolved into a saved snapshot; resume retains it, while new spawns can see edited roles. Parent/ancestor/current-root permissions and shell/plugin capabilities only tighten authority, including sibling input and later read-only review. Explorers remain Plan-only. A child report is teammate guidance: it cannot start an idle root, create a goal or authorize more privileged work. See [AGENT_ROLES.md](AGENT_ROLES.md).

One root and its descendants may work concurrently in a workspace; unrelated roots in that workspace remain exclusive. Other workspaces run independently. Shared file transactions preserve optimistic versions, and group review avoids attributing one worker's changes twice. Parent completion waits for actual child and command results. Follow-up admission stays active across final-save and new-turn reservation windows. Coordinator status publication checks current engine run/state under serialized mutation: delayed old running or completion observations cannot revive a finished run, erase a reserved follow-up or replace a newer run.

Plan-mode root and child questions are published inline, with answers tied to their exact child/run/call. Choice/freeform/skip validation, reconnect, cancellation and restart repair preserve that ownership. There is no separate Agents panel; native child activity and required controls remain part of the conversation.

Thread naming uses a separate bounded `gpt-5.6-luna` / `low` metadata request with no tools and a strict title schema. Its pinned profile must support those options; unavailable configuration is reported rather than substituted. Useful prompt titles appear immediately, manual titles win over late responses, and unfinished accepted naming work has bounded recovery. Completed titles are not regenerated by reads or ordinary restarts.

## Context, usage and goals

Automatic semantic compaction defaults to **90% of the full declared context window**: 945,000 tokens for Astra/Sol/Terra/Luna and 360,000 tokens for Cyber/Daybreak. Thresholds are editable per profile. The old 360,000-character trigger is not the current policy. Effective admission capacity defaults to 95% of the published window, leaving 5% headroom; it is separate from the 90% compaction trigger.

Current context uses the latest valid provider context-usage baseline plus disclosed incremental estimates for subsequent input, overhead and applicable opaque-state accounting. Cumulative billing totals do not trigger compaction. Missing or incompatible baselines fall back to labeled estimates, not invented measurements. The actual provider reasoning-included signal prevents double counting; cached input and reasoning output subsets are not charged a second time as additional totals.

Independent local guards still cover request bytes, images and item counts. Current source uses a 48 MiB wire compaction trigger, a 96 MiB hard input-wire bound, 64-image compaction/128-image input bounds, and a 16,000-item compaction trigger within a 20,000-item history bound. These are application transport/resource limits, not alternate advertised model capacities. A genuine provider context-limit error supplies a separate recovery signal without automatically replaying the failed request.

Automatic and manual compaction call a real tool-free structured helper using the accepted model options and a bounded summary budget. Objectives, current attachments and recent complete tool rounds remain protected. Cancellation, stale/cancelled input, invalid summaries or failed commits preserve the prior model head. Queue, title and goal changes are not overwritten. Full transcript/journals remain durable; excessive protected context fails visibly instead of being silently clipped or replaced with invented summaries.

Context details contain the selected conversation's own usage, its native-descendant subtotal and their combined reported usage. Each descendant has its own context/capacity; there is no family context percentage, app-wide/lifetime counter or public last-response card. Missing counters and unavailable records stay explicit. Exact values remain available in details/accessibility; the context bar uses at most three significant digits. [CONTEXT_USAGE.md](CONTEXT_USAGE.md) describes the bounded, source-bound derived records and subtree paging.

Goals require explicit user/UI intent. Saved goal identity/revision and accepted options govern bounded automatic continuations, pause, budget stops and restart behavior. Reported root/descendant work and applicable foreground helper usage are charged under the sampled goal identity; stale completion cannot finish a changed objective. Compaction and generated-image usage are rechecked before further work. An exhausted earlier goal does not charge an independent Plan request. Optional background memory costs have their own job/admission accounting. See [GOALS.md](GOALS.md).

## Forks, file rewind, review and worktrees

Explicit root forks retain the selected completed history and authorized attachment/review references, with no live child/browser ownership or inherited active goal. Archive/restore and conversation-only rewind remain available. Conversation rewind preserves a durable original and restores the removed prompt/attachments to the composer; it does not itself undo files.

The implemented optional **reviewed file/index rewind** uses actual before/after checkpoints for excluded turns, concrete bounded previews, signed current plan/version authority, dirty-editor checks and file/index conflict validation. It restores selected captured deltas while preserving unrelated working files and staging. It does not reset/clean the checkout, move branches/HEAD, rewrite remote history or invent unavailable old snapshots. Missing coverage remains a visible reason to choose conversation-only rewind.

Restore transactions retain exact transcript/journal and file/index backups, conditional source cutovers and recovery fences. Unsupported atomic operations or last-moment conflicting writers fail closed. Startup/status reads expose uncertain recovery; they do not silently resume a restore or discard its backups. Settlement requires current verified authority, including the explicit Keep current path. This is the user's requested extension: the pinned CLI retired `ghost_snapshot`, so current file rewind is not attributed to an active upstream ghost-snapshot implementation. See [GIT_FILE_REWIND.md](GIT_FILE_REWIND.md), [GIT_REWIND_UI.md](GIT_REWIND_UI.md) and [checkpoint storage](../server/git-checkpoints/README.md).

Keep/Undo is a separate change-review workflow. Direct writes/patches preserve precise content/mode snapshots; shell capture observes bounded regular-file changes. Undo preflights the complete selected set against current bytes, paths, types and modes; conflict returns 409 without partially undoing that selection. Keep resolves review records. Neither action commits Git history. Overlapping manual editor/Git/terminal work is conservatively excluded from broad shell attribution, with visible warnings; external host processes cannot be attributed with certainty.

Structured reviews use real Git targets and immutable captured sources, strict findings and read-only root/child policy. Review source navigation remains available after live files change. Managed worktrees are actual linked Git checkouts; activity and removal fences preserve dirty/untracked work, commits and recovery ownership. Worktree removal does not force deletion or create a container/mount. See [CODE_REVIEW.md](CODE_REVIEW.md) and [WORKTREES.md](WORKTREES.md).

## Skills, hooks, search and memories

Project workflows expand `.codex/workflows/<name>.md` while retaining the user's short command. Skills and enabled plugin resources use scoped bounded discovery, persisted explicit selections and normal instruction precedence. An explicitly authorized skill may pass to workers; model-generated assignment text cannot authorize an explicit-only skill. MCP is neither discovered nor started.

Enabled native command hooks participate in admitted Agent runs. PreTool rewrites re-enter validation and actual Ask approval; a hook saying Allow cannot approve the action. PostTool feedback cannot undo an executed side effect. Stop continuation and background processes are bounded and cancellable, with shared change review and exact owned approvals. Plan, captured review, disabled shell/plugin roles and manual compaction do not run hook commands. Cleanup retains its bounded deadline and inherited restrictions. [HOOKS.md](HOOKS.md) documents the supported events and deliberate differences.

Hosted Responses search supports cached/live/disabled preferences and real streamed activity/citations. Reviews, budget wrap-up and title/summary/memory helpers do not search. Safe observed source metadata is retained; secret-bearing URLs and stale citation offsets are not replayed. Any bounded stateless search-history supplement is explicitly untrusted historical data. No search results or public reasoning summaries are fabricated. See [WEB_SEARCH.md](WEB_SEARCH.md).

Memory generation and use are independent and default off. Current source implements ordinary-root activation/startup discovery, real cited extraction, **workspace-scoped consolidation**, native `memory_list`, `memory_read` and `memory_search`, and authenticated bounded pipeline status. Startup is metadata-first and bounded; constructors, status reads, polling and restart recovery do not spend requests or replay uncertain jobs. Missing historical model snapshots are reported rather than guessed.

Extraction and consolidation use accepted model snapshots and separate bounded admission accounting. Consolidation is an isolated tool-free structured Responses worker; the server validates exact source IDs/revisions/quotes and publishes immutable dependent artifacts atomically. Logical paths include `memory_summary.md`, `MEMORY.md`, `rollout_summaries/<thread-id>.md` and optional `skills/<slug>/SKILL.md`. The optional Markdown is not installed as an executable skill, hook or plugin. Extraction/consolidation share a 24-request rolling-day admission budget and one active lane, with a two-request daily consolidation sub-limit. Failed/uncertain attempts are not refunded by Clear.

Eligible ordinary roots in Agent or Plan can use bounded read-only memory tools. Recall and tool payloads are private request overlays: they do not enter saved provider input, journals, compaction, forks, child briefs, generic hooks or public activity. The durable tool result is content-free and payloads are revalidated before reuse. Current-thread/foreign/stale sources are excluded; edits, opt-out, deletion, rewind, stop and logout revoke affected access/publication. Metadata-only consolidation events do not erase valid recall. Optional storage failures are visible while ordinary foreground work can continue.

Upstream **cross-workspace/global-user consolidation**, model-facing ad-hoc memory writes, counted memory citations/usage-ranked retention and all upstream version/import/configuration variants remain outside this implementation. Background helper usage is recorded on its jobs, separately from conversation/goal totals. Scheduling assumes one application process owns a state directory; bucket markers do not establish distributed leases. See [MEMORIES.md](MEMORIES.md) and [MEMORY_PARITY_PLAN.md](MEMORY_PARITY_PLAN.md).

## Images, files and native browser

`view_image` sends actual validated local PNG/JPEG/WebP/GIF bytes as structured image input, with guarded reads and bounded dimensions/size. Image and general-file messages are durable attachments with exact thread-reference authorization. Waiting/cancelled references confer no access. Inspection is bounded and workspace copies use the normal permission/change-review boundary. Explicit root forks retain authorized delivered references; native children do not inherit them implicitly.

Native `generate_image` is wired as a separate hosted-image Responses helper through the same fixed endpoint, using the accepted conversational model/options and host instructions. The source supports generation and bounded reference-image editing; the recorded current live proof establishes generation, not every edit/partial-preview behavior. The helper alone advertises the hosted image tool. Unrelated naming, compaction, memory and probe calls do not gain image generation.

Generated originals are immutable validated assets. Native list/read tools, exact request-local pixel replay, chronological image cards, authenticated previews, create-only Save and public Download are connected. Durable history holds authorized references/metadata rather than base64 copies. Manual originals/save/download support up to 8 MiB; permission-controlled `copy_generated_image` remains capped at 2 MiB and reports actual Undo coverage. Helper usage belongs to the calling thread/applicable goal and cannot replace its ordinary context baseline. See [MULTIMODAL_PARITY_PLAN.md](MULTIMODAL_PARITY_PLAN.md).

Downloads stage immutable objects in the separate public `alvin3y12/codex-downloads` bucket, use direct public links and expire after 24 hours with startup/scheduled cleanup. Workspace uploads stage directly from the browser through that public transfer protocol, then the server verifies/imports them into the chosen workspace; staging expiry does not remove permanent files. The bucket is never mounted. If the browser blocks a cross-origin public fetch, the actual clickable public-link fallback remains and says **Download requested**, without claiming a saved browser file.

Native browser service, engine tools, authenticated routes, lifecycle cleanup and the React viewer are wired in source. Agent exposes `browser_open`, `browser_observe`, `browser_act` and `browser_close`; Plan omits `browser_act`, with matching execution guards. Existing no-shell roles receive only browser inspection/navigation/close. Current root and inherited child restrictions intersect; reviews and title/compaction/memory/budget helpers receive no browser tools. Real text/image output is forwarded to the model and readable activity stays in the existing chronology.

Scope comes from the exact engine workspace/thread/run, never tool arguments. Ask uses the normal approval queue; Full access skips ordinary origin/action prompts, while an untrusted local-preview origin still needs explicit admission. Hook rewrites, budget changes, page generation/observation and exact target are rechecked. Closing/retiring a browser cancels its exact pending approval, including an associated PermissionRequest-hook approval, without clearing a newer approval or stopping unrelated work.

Each session owns an ephemeral browser process/context outside public `/data`. Native children and explicit forks do not share browser state. Normal turn completion retains the session; idle expiry, exact thread/workspace retirement and shutdown drain it. Current bounds include two live/draining sessions, four total tabs, a 1280 × 800 viewport, 30-second operations and 2 MiB screenshots. A failed close keeps its process/profile/capacity reservation until actual exit and cleanup.

The source includes destination/origin guards, an immutable DNS cohort and fixed native transport policy while preserving browser TLS/CORS/CSP. Manual takeover/release uses authenticated generation-bound controls. Private values stay out of model requests, hooks, ordinary state and logs; agent screenshots are withheld after private manual input when image redaction cannot be established. The viewer does not embed arbitrary remote HTML or expose CDP/launch flags. Browser-native upload/download integration, annotations, richer navigation/developer controls, durable protected sign-ins and personal-browser extension integration remain separate unfinished scope. See [BROWSER_PARITY_PLAN.md](BROWSER_PARITY_PLAN.md) and its dated [safety review](BROWSER_SAFETY_REVIEW.md).

**Native browser host limitation:** the coordinator's current Hugging Face probe used UID 1000, the matching full Chromium build and official native libraries, and still failed with **`No usable sandbox`**. Ordinary UI-browser/controlled-adapter tests do not turn that failure into an executing hosted browser or network-containment proof. The service retains its required normal sandbox and visible startup failure. The user hosting/scope choice remains pending; no consent to change that boundary is inferred here.

**Realtime audio is excluded** under the latest user instruction after the exact fixed endpoint rejected documented audio-session startup and required Responses `response.create`. Voice controls remain absent. No alternate audio provider, browser speech service or proxy is substituted, and realtime is not a release/goal blocker. ## Persistence and bounded presentation

Authoritative workspace files, instructions, reusable configuration, threads, model input/journals, goals, reviews, checkpoints, native-agent registry, memory records and required assets live on native `/data`. Ordinary data is unencrypted in the explicitly public bucket; account credentials remain protected separately. Saved GitHub connections and repository/account choices survive logout and restart. Normal startup does not reset user data. The Python ZeroGPU entrypoint's no-op GPU wrapper starts Node; it does not provide a second application backend or launch containers.

Serialized JSON writes, exact source receipts, deletion tombstones and guarded conditional filesystem publication protect ownership/recovery. Native PTY/filesystem bindings support the Node implementation; they are not the Rust Codex runtime. Public APIs do not return full private thread records or opaque reasoning. Known credentials are redacted across stream boundaries as well as from tool/log/history text. No managed-model user credential is stored; `placeholder` is the fixed non-secret connection value.

Ordinary workspace deletion moves files into persistent recoverable trash with a verified 30-day deadline. Authoritatively GitHub-backed workspaces use confirmed permanent local deletion. Mutable account selection alone cannot classify provenance. Permanent cleanup is generation-bound and preserves unresolved recovery ownership; verified missing directories leave the active list. Frontend handling retains dirty editor buffers and current workspace/run fences.

Conversation history, directories and other large lists use bounded pages/visible rows. Large editor files use bounded byte windows and guarded range saves; a page's text never replaces an entire large file. Signed/versioned stale cursors and unavailable source state fail visibly. These presentation limits do not truncate the durable model transcript or pretend an incomplete listing is exhaustive.

Representative agent bounds remain 64,000 prompt characters, 1 MiB direct file writes, 2 MiB patch input, four command sessions per run, ten-minute command lifetimes, eight concurrent native agents and three delegation levels by default, and 80 Responses iterations per run. Image inspection is capped at 8 MiB, 16,384 pixels per side and 40 million pixels. Stream/tool truncation and quota failures are explicit. Exact feature-specific limits and paging contracts live in their implementation and [API.md](API.md).
