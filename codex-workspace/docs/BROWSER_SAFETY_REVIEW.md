The current service lazily imports Playwright only after rejecting parent debug/file/profiling settings. Its public startup failures distinguish unsupported native sandbox setup without forwarding raw launch errors. The viewer retains a stable private-input marker when text is revealed so its decorative input-caret controller can never mirror that value. It bounds bytes during receipt and preserves fractional pointer-up positions until an authenticated click consumes them. These fixes close concrete source/UI gaps; they do not substitute for native privacy sentinel checks after integration.

Workspace lifecycle quiescence is separate from the pure signed-state deletion preflight. Its token-owned lease closes only the admitted target's browser sessions and blocks reopens/input through archive or removal publication. Every caller releases only its own token, including failure paths; failed native closes retain their existing draining reservations. Workspace trash/missing retirement, metadata archival and managed-worktree native/artifact stages revalidate their authority after awaiting closure. Existing terminal and recovery semantics remain intact. The coordinator must wire this lease-returning hook; calling `closeWorkspace` alone would leave a reopen window before metadata publication.

Closing that browser also cancels its pending approval. `BrowserExecutionScope.approve` receives the browser lifetime signal as a separate trusted second parameter; it is never part of the request, model arguments or durable JSON. Service cancellation listens to both that lifetime and the run signal, removes its listeners on every settlement and rechecks after an answer. It never aborts the surrounding run. The engine consumer owns exact pending-approval settlement and must drain it before later tools can overtake cleanup. Ownership, generation and observation checks remain required after cancellation as well as after approval.

Required native acceptance remains: real screenshot and counted input; CORS success and denied writes; first popup/worker/frame/socket destination counters; actual DNR WebTransport UDP denial plus a working control; native DNS pinning and rebinding resistance; generation/approval freshness; exact-session auth revocation; private-input sinks; startup/capacity/retirement/restart; and actual model text/image/tool delivery through the fixed endpoint. A missing browser or a skipped gated suite cannot satisfy any of these.

### Useful pinned-dependency evidence for the fixes

Playwright 1.63.0 does support public `AbortSignal` options for `ElementHandle.click`, `fill`, `selectOption`, `type`, and `press`. For example, `types/types.d.ts` lines 13044–13053 documents click cancellation; `coreBundle.js` lines 60872–60905 forwards the options through the frame timeout settings, and lines 63871–63901 sends the actual `__abort__` request. The initial assumption that every action requires destroying the tab is therefore too broad. `ElementHandle.focus` and the page mouse/keyboard helpers used by this draft use the no-timeout channel path and still need dispatch fences or target teardown when necessary. These source references establish an available API, not that the service's race handling has passed.

The shared `createRedactor` deliberately ignores supplied secrets shorter than eight characters. Passing a six-digit OTP or three-digit CVC to it unchanged does not protect that value. Browser-private redaction must account for this without putting manual input into hooks, conversation history, or ordinary state.

Production log configuration is part of the privacy evidence. The pinned Playwright client can log raw channel messages when its debug namespace is enabled (`coreBundle.js` lines 63878–63880); these messages include fill and insert-text arguments. A restricted Chromium child environment does not disable the parent Node library's logger. No such logging is claimed to be enabled by default here. The coordinator must verify that production debug/tracing configuration cannot publish manual input and use disposable sentinels when checking logs.

## Network conclusions that source inspection can and cannot support

The initial policy rejects credential-bearing and unsupported URLs, nonpublic address literals, mixed public/private DNS answers, local aliases, and unadmitted loopback origins. Local exceptions use an exact origin and exclude the application port. Origin navigation permission is separate from public subresource admission. Service workers are disabled; the draft also tries to block workers, cross-process frames, and unmanaged popups. TLS errors and CSP bypass are explicitly disabled. The service exposes no arbitrary browser JavaScript, CDP, launch flags, cookie API, or debugging endpoint to model arguments.

Those are useful controls, but Node DNS preflight does not pin Chromium's actual resolver or its connected address. The plan correctly labels this limitation. Calling `grantPermissions([])` uses Chromium's permission-denial override according to local Playwright source; that is not evidence that every main-frame navigation, WebSocket, or rebinding case is covered by native local-network enforcement. Main-frame navigation and public-to-private rebinding need separate real tests.

Replacing Playwright HTTP routing with raw CDP can avoid BR-01, but it must not introduce a first-request gap for popup documents or worker scripts. Public local protocol types expose a browser CDP session, target auto-attachment, `Target.closeTarget`, and legacy non-flat target message forwarding. `CDPSession.send` has no public top-level session-ID override. The existence of those types does not establish all browser-level non-flat behavior or allow callers to instantiate arbitrary flat child sessions through a public Playwright API.

Playwright independently enables its own root auto-attachment (`coreBundle.js` line 38366) and resumes new pages and workers (lines 37670 and 37840). The protocol's `waitForDebuggerOnStart` description alone does not prove that a second controller prevents the first network bytes from leaving. Closing in `context.on('page')` is too late to establish that guarantee: the pinned public page-event documentation says the popup response has already begun loading by then. A proposed root guard requires executable proof, not an assertion inferred from its name.

The subsequent `network.ts` source pass found the intended stronger mechanism: browser-level Fetch is installed before any context exists, a bounded legacy envelope addresses the controller's own flat child sessions, unknown frame IDs are denied, and request admission is checked again after asynchronous work. Its owner traced the corresponding browser Fetch handler and independent per-session V8 debugger barriers in the pinned Chromium/V8 sources. This improves the source basis; it still needs the shipped binary's first-hop and cross-realm constructor tests. In particular, a synchronous `window.open('about:blank')` followed by use of that window's native WebSocket constructor must not create a setup-time escape.

The initial context-wide WebSocket handler also infers the initiator from the sole managed tab because the public socket route supplies no frame. It cannot prove that an unknown popup or worker initiated a local socket under the intended page's authority. BR-10 additionally establishes a direct source-level bypass of that routing layer. Use a native attributable controller or deny the unestablished exception; do not use either a tab-count heuristic or page-side JavaScript wrapping as evidence of destination enforcement.

The network implementation owner subsequently inspected the pinned Chromium tag and identified a separate **WebTransport coverage gap**. Its dedicated HTTP/3 client does not establish denial through the generic QUIC policy flag; the source explicitly leaves that policy check unfinished. The candidate Fetch/WebSocket controller must not claim to cover this path or rely on a speculative Blink-feature switch. [Pinned dedicated WebTransport client](https://chromium.googlesource.com/chromium/src/+/refs/tags/153.0.8010.12/net/quic/dedicated_web_transport_http3_client.cc), [pinned network-service WebTransport setup](https://chromium.googlesource.com/chromium/src/+/refs/tags/153.0.8010.12/services/network/web_transport.cc).

That client's local-network check runs before UDP socket creation, but the pinned checker permits potentially trustworthy same-origin requests before asking permission and permits requests to an address space that is not less public. These exemptions include local-preview-to-loopback traffic. Consequently, denying native permissions does not implement this application's exact-port policy or close the trustworthy-same-origin rebinding case. This is a source-supported policy mismatch and a remaining production release blocker, with native traffic evidence still pending. [Pinned local-network checker](https://chromium.googlesource.com/chromium/src/+/refs/tags/153.0.8010.12/services/network/local_network_access_checker.cc).

## Integration and parity status

The reviewed trusted-scope checks bind model access to the exact supplied workspace and thread, and Plan definitions omit the generic interaction tool with a matching execution guard. This relies on the coordinator constructing scope from the actual run and intersecting child/root capability restrictions; model-provided identities must not be accepted as authority. Authenticated UI users share the application's one workspace-owner authority, so lack of separate multi-user ACLs is not itself a finding.

No mounted-route, deletion/shutdown, or model-output/history/UI integration evidence was supplied for this closure. These remain coordinator-owned gates. Browser-private messages must stay outside engine activity-input persistence and hook callbacks. Ordinary browser observations intentionally sent to the model follow the explicitly public conversation-storage policy; no generic claim of private browser history is warranted.

The plan leaves automatic transfers, annotation/style feedback, richer developer diagnostics, saved protected sign-ins, and personal-browser extension integration incomplete. Native WebSockets are denied, and some worker/frame attempts close their creating tab. Agent images are withheld after manual private input. These are practical parity limits that must remain visible in the product and release description.

**Verdict: the reviewed source remedies are ready for coordinator validation.
