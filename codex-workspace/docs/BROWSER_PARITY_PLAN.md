## Implementable first increment

Use the native Node service with `playwright-core` and the matching full Chromium build in headless mode. Headless-shell lacks the required native extension policy. Fixed validated operations run directly on the authorized host. The browser uses its ordinary built-in security sandbox and renderer/process isolation, which the user explicitly allows. The service does not create a separate container, VM, manual namespace wrapper, MCP server, proxy or model endpoint. Do not borrow browser-test flags that disable the production security contract.

One ephemeral browser context belongs to one exact workspace and thread. A child receives a fresh context and the allowed runtime configuration, never its parent's cookies, pages, screenshots or history. Explicit user-created conversation forks also start without a live browser session. Contexts remain available between turns while the instance is alive, expire after inactivity, and close on thread/workspace removal, explicit close, cancellation requiring process teardown, or shutdown. Restart reports that the live browser ended; it never reconstructs a logged-in profile or silently repeats a form submission.

The initial limits are one dedicated Chromium process per session, two live or draining sessions, four tabs in total, a 1280 × 800 viewport at device scale 1, 30 seconds per operation, 200 element references, 32 KiB observation text, 128 KiB total serialized observation, 50 recent console/network notices, 64 origin grants (at most 16 local), and 2 MiB per screenshot. A failed shutdown retains its process/profile reservation until actual native exit and cleanup. Limits produce named failures or explicit truncation. Browser startup returns an actionable unavailable error, including a distinct host-sandbox error; it never generates a substitute page or fabricated screenshot.

Source lives under `server/browser/`, `client/components/browser/` and focused browser tests. The coordinator owns shared types, engine/transport integration, the viewer entry point, auth/lifecycle wiring, package/bootstrap changes and API documentation. The browser module's factory accepts `AppContext`; tools and authenticated routes share its singleton. Thread deletion calls `closeThread` for the exact deleted threads, and server shutdown awaits `shutdownBrowser(ctx)`. Normal turn completion retains live sessions; a conversation fork does not copy one. The router requires `{ acquireControl(req) }`, returning a disposable `{ signal, authorize, dispose }` from real middleware authentication, and fails closed if omitted. Its exact session identity and expiry must cover revocation and request disconnect. Queued actions revalidate before dispatch/response, pending native actions receive cancellation, and the router disposes subscriptions on finish, error or abort. Revocation does not stop unrelated agent work.

Workspace retirement uses the optional `WorkspaceLifecycleOptions.quiesceWorkspace(id): Promise<void | (() => void)>` hook, wired to `getBrowserService(ctx).quiesceWorkspace(id)`. The returned lease is held through authoritative archive/removal publication and released in `finally`. Token ownership keeps nested/retried callers from releasing each other's holds. New opens and agent/manual input for that exact workspace are blocked while its current sessions close; new opens also require `getAvailable` and recheck admission afterward. Ordinary trash, verified-missing retirement, metadata Archive, permanent purge and managed-worktree removal/recovery invoke the hook only after their existing admission checks. They revalidate registration/native/removal authority after the await. Pure deletion preview and `assertWorkspaceDeletionAllowed` have no closing side effects. Existing missing-directory/managed-Archive terminal behavior is preserved, and family Git fences never close sibling browsers. A close failure preserves current bytes or the already-reached recovery journal; it does not replay native deletion. The lifecycle tests use real files/Git and held close barriers, without claiming an executing Chromium process.

## Tool and integration contract

The module exports `browserToolDefinitions(mode)`, `isBrowserTool(name)`, `executeBrowserTool(ctx, name, args, scope)` and `getBrowserService(ctx)`. Scope is supplied by the engine, never the model: workspace/thread/run identity, Agent or Plan mode, Ask or Full access, AbortSignal, redactor and an approval callback. The trusted callback is `approve(request, lifetimeSignal?)`: its second argument is the exact ephemeral browser lifetime, never a serialized request field or model argument. Browser closure races this signal alongside the run signal, cancelling only that pending browser approval with `BROWSER_ABORTED`; the engine must settle its exact approval queue/UI record without aborting other work. Existing generation/document checks still apply after any answer, including a late Yes. Results separate actual model output from readable activity text:

```ts
type BrowserToolResult = {
  output: string | ModelItem[];
  logOutput: string;
};
```

| Tool | Inputs and real behavior |
| --- | --- |
| `browser_open` | HTTP(S) URL, whether to open another tab, and optional exact public `network_hosts`. Validate the destination and origin grant, create/reuse the caller's context, navigate, and return a real observation. Public DNS addresses are pinned when that process starts; newly needed CDN/API hostnames require explicitly closing and reopening it, losing ephemeral login/page state. Never silently replace an existing session. An explicitly admitted loopback preview is separate from public browsing. |
| `browser_observe` | Optional owned tab ID and screenshot flag. Return current URL/title, bounded visible text, a bounded list of visible interactive elements with opaque references, viewport, observation ID, tabs and recent failures. Screenshots contain actual captured bytes as `input_image` with `detail: original`. |
| `browser_act` | Owned tab, exact observation ID, and one bounded operation: click by current reference or viewport coordinate, fill/type, keypress, select, or scroll. Resolve the real target, validate permission and state again after approval, act once, then capture the result. No arbitrary selectors, scripts, browser launch arguments or CDP methods are accepted. |
| `browser_close` | Close one owned tab or the caller's browser session. Invalidate references and queued operations; closing the final tab retires the context. |

Plan exposes observation/navigation/close, never interaction tools. Review, title generation, semantic compaction, memory helpers and budget wrap-up receive no browser tools. Browser availability is intersected with inherited child restrictions and active root restrictions just like native shell tools. Hooks may block or rewrite inputs, but rewritten inputs must pass normal validation and permissions again.

The engine emits readable activities in the existing text/reasoning/tool chronology: for example, “Opened example.com”, “Selected Search”, or “Browser could not connect”. The model gets actual observations, not protocol JSON printed into chat. Activity text excludes image data, cookies, headers and passwords. The result may contain an authenticated preview action; do not expose a Chromium debugging endpoint or proxy raw page HTML through the application's origin.

Cancellation must invalidate an operation before awaiting teardown. A JavaScript timeout alone does not cancel a Playwright action. Pinned Playwright 1.63 supports `AbortSignal` on element actions; use it and await pending input before takeover/release finishes. Close a stuck target when a non-cancellable mouse/keyboard/focus dispatch cannot settle. Revalidate a click target after its input-free actionability trial, then hit-test and dispatch pointer input without entering another long actionability wait. A click already delivered before Stop can have a real effect; report that boundary honestly rather than claim it was undone.

## Access, privacy and host boundaries

Origin access and action approval are separate. An origin grant is tied to the exact thread and normalized origin. Preserve the existing Ask/Full access behavior through the engine approval callback, including genuine existing authorization and denial. Full access must not become a new series of routine approval dialogs. An origin grant is not permission from page content to send credentials, change access or perform a consequential external action. Password entry and account handoff belong to manual control; website text cannot grant permission or change runtime rules.

Bind any pending approval to thread, run, session generation, tab, observation, URL and exact operation. Revalidate all of them after the answer. Denial, Stop, manual takeover, changed page state and closed sessions prevent execution. A stale approval must not affect another page or workspace.

Every navigation, redirect, popup, subresource and WebSocket needs a destination check. Accept HTTP(S) only for navigations; reject URL credentials, `file:`, browser-internal schemes, private/reserved IPv4/IPv6, mixed public/private DNS answers, local hostname aliases and metadata endpoints. Block service workers so request interception remains effective. Keep browser TLS, CORS and CSP enforcement intact; grant no camera, microphone, clipboard or local-network permissions. Chromium's denied browser permissions supplement request checks.

A local development exception must name one loopback origin and port, be bound to the workspace/thread, exclude the application server and reserved services, and be admitted through explicit user action or a trusted native-process registration. An agent-provided URL alone cannot declare itself trusted. The coordinator approved local frontend/API requests only when both exact origins were independently admitted for that same thread/workspace; native CORS still applies. Requests from public pages must not gain this exception merely because the same session once previewed a local app. Do not offer unrestricted LAN access.

**Network release gate:** Node preflight alone does not pin Chromium's resolver. `dns-pins.ts` now builds a bounded immutable process-lifetime cohort of validated literal addresses, rejects mixed/private public answers, and denies undeclared hostname resolution through native resolver rules. The original hostname remains in browser URLs, origins and TLS validation. A fresh browser disables H2/QUIC alternative-server negotiation; this is separate from the transport gate. Native resolver behavior and its local positive control still need actual execution. Browser-wide native Fetch admission binds every redirect to its first intercepted URL and owning document. It does not use Playwright's routing helpers: pinned `route` synthesizes CORS preflights, while `routeWebSocket` has page-callable pass-through helpers. Native CORS success/denial, first popup/worker requests and socket counters require real browser proof.

`transport-policy.ts` supplies a source candidate for the earlier WebTransport gap: one fixed first-party native declarative policy denies all WebTransport and WebSocket requests before connector creation. It has no background code, content script, user-supplied extension path or public extension-loading API. Startup verifies the pinned full-browser version, immutable files, installed inventory and actual compiled matchers in two disposable incognito contexts before website contexts exist. Readiness is not egress proof. The gated real fixture counts UDP at an unapproved local port and requires a positive control after removing the rule from its disposable browser. Native local-network permission denial and `--disable-quic` alone do not cover this dedicated client. [Pinned WebTransport interception](https://chromium.googlesource.com/chromium/src/+/refs/tags/153.0.8010.12/extensions/browser/api/web_request/web_request_proxying_webtransport.cc), [pinned local-network checker](https://chromium.googlesource.com/chromium/src/+/refs/tags/153.0.8010.12/services/network/local_network_access_checker.cc)

Browser contexts separate sessions and do not supply an OS security boundary. Production arbitrary browsing remains unaccepted until the native guards, host startup, privacy, cancellation and provider gates pass. Preparing integration does not change that acceptance status.

Profiles, cookies, local/session storage and temporary downloads stay on validated ephemeral instance storage, outside PUBLIC `/data`, and never enter logs, ordinary JSON state, source or provider tool results. Before lazily importing Playwright, the service rejects parent-process `DEBUG`, `DEBUG_FILE`, `PWDEBUG`, its npm aliases and profiling configuration. Filtering the Chromium child environment alone cannot protect manual values from parent protocol logs. A subprocess regression proves that refusal occurs before `DEBUG_FILE` is created. Do not reuse the application login cookie or decrypt GitHub tokens for browser sessions. Manual keystrokes are private control messages; neither the agent nor hooks see them. If durable browser sign-ins are added later, credential material requires `ctx.secrets`, explicit origin scoping and restart tests.

During takeover, stop agent access to screenshots, page observations and actions until authenticated release. Keep private manual values in bounded session-only memory, including short OTPs, and redact their later text/title/console/URL reflections. Recognize tokenized autocomplete fields, omit form values from observations and mask sensitive controls in previews. DOM masks cannot certify arbitrary canvas/image reflection, so the draft withholds agent screenshots after private manual input for that entire ephemeral context; authenticated user previews remain available. Browser observations explicitly sent to the model follow the application's existing public conversation-storage policy. Screenshots or annotations saved into chat are ordinary durable artifacts and must not be mislabeled private.

## User surface and proposed authenticated routes

Open `BrowserSessionPanel` from a chat activity or the existing top-bar overflow; avoid a new rail or Agents panel. It accepts `{ workspaceId, threadId?, locked?, onNotify, onClose? }`; supplying `onClose` opens its modal, otherwise it renders an inline section. It shows the actual screenshot, URL/title, tabs, refresh, takeover/release and session end, with page-control selection, private input, keys and scrolling during manual control. Refresh obtains a fresh observation; it does not claim a navigation reload. Back/Forward/Reload navigation remains a follow-up. Preserve editor buffers and terminal sessions. Phone controls have at least 44-pixel targets; pointer coordinates retain the native fractional position before mapping into the screenshot viewport. Responses discard stale workspace/thread/control results and release image URLs on close or lock. Private input remains marked `data-private-input="true"` even when revealed, and must retain its native caret without value mirroring. Image streams stop at 2 MiB even without Content-Length. Remote third-party HTML never enters the application DOM.

All routes mount behind existing authentication and mutation same-origin checks. Suggested narrow routes:

- `GET /api/browser/sessions` and `GET /api/browser/sessions/:id`: bounded metadata only.
- `GET /api/browser/sessions/:id/preview`: `Cache-Control: no-store`; paired `generation` and `observation_id` are required for manual control. The response returns retained immutable observation bytes and `X-Browser-Observation`, `X-Browser-Generation`, and `X-Browser-Tab`. Stale IDs fail; never expose a public debugging URL.
- `POST /api/browser/sessions/:id/takeover`: invalidate queued agent actions and claim manual control.
- `POST /api/browser/sessions/:id/observe`: return fresh manual observation/element references, requiring the exact takeover generation.
- `POST /api/browser/sessions/:id/action`: validated manual input against current tab/session generation; no request-body logging.
- `POST /api/browser/sessions/:id/release`: explicit return to agent after the user finishes.
- `DELETE /api/browser/sessions/:id`: close the real context and retire state.

Closing/hiding the browser viewer does not mean a website operation completed. Show real failures, the active page and who currently has control. Auth loss prevents further preview/control access. A future annotation action must freeze its screenshot, page URL, viewport and selected element/rectangle with the user's text so feedback remains meaningful after navigation.

File transfer needs explicit follow-up integration. Browser downloads must not silently land in PUBLIC workspace state or create direct links before the user's existing download workflow stages them. Browser uploads must use a specifically selected workspace file and destination, with symlink/opened-file checks and the existing authorization; do not let a generic file chooser expose host paths. Keep blocked/unsupported transfer behavior visible until this path is implemented and verified. This is a remaining parity task, not a claim that transfers are impossible.

A trusted Node preparation step invokes the installed `node_modules/playwright-core/cli.js install chromium` with a controlled `PLAYWRIGHT_BROWSERS_PATH` under `/tmp`. ## Verification required before calling this parity complete

1. **Real local browser:** in the coordinator's launch window, use a disposable local app with accessible controls, a result counter, a popup and distinct visual markers. The production service must open it, observe actual DOM, click/type/select/scroll, preserve state between calls and return a screenshot whose pixels and dimensions are checked. Missing binary/library tests must surface unavailable errors.
2. **Real provider loop:** through the unchanged fixed Responses endpoint, ask the selected catalog model to inspect an unknown visual marker and complete a simple fixture interaction using these tools. Prove the resulting app state independently. Retain sanitized evidence of emitted tool calls, actual state and screenshot delivery. Do not treat scripted provider tests as this proof; do not query `/models` or add provider controls.
3. **Permissions and isolation:** deny an origin/action and verify fixture counters remain unchanged; permit an action and verify one execution; change the page during approval and verify rejection. Exercise Full access, Plan, child contexts, stale approvals, Stop, takeover/release, changed workspaces, context capacity, idle teardown and restart. Confirm no cookies or keystrokes appear in public state/events.
4. **Network negatives:** real fixtures for cross-origin redirects/popups, external pages referencing private HTTP/WebSocket endpoints, IPv4-mapped IPv6, hostname aliases, mixed DNS answers, DNS rebinding, service workers, `file:` and browser-internal navigations. Check the private fixture's request counter, not just the tool's error message. Independently verify legitimate local preview still works and cannot reach other loopback ports or the app API.
5. **Authenticated UI:** live preview, keyboard/touch control, resize coordinate mapping, phone navigation, reconnect, expired login, same-origin rejection, visible permission failures and preserved editor/terminal state. The agent must be unable to observe or act while the user owns takeover.
6. **Hosted native startup:** publish only after the immediate release gate; prove matching binary/native libraries install in the real ZeroGPU Space, Chromium launches without prohibited machinery, and the same interaction works after a normal fresh instance start. Evaluate process/RAM capacity under two sessions. Do not claim hosted viability solely from this development machine's cache.

The first fixture sources are `tests/browser-policy.test.ts`, `tests/browser-service.test.ts` and `tests/native-browser-fixture.ts`. The native suite is explicitly gated by `CODEX_NATIVE_BROWSER_TESTS=1`; its skipped default is not a pass. It uses actual HTTP servers, Chromium input, screenshot bytes and destination counters. First-increment acceptance establishes genuine native interactive browsing. The draft fails closed on unmanaged popups, workers, cross-origin/cross-process embedded frames and automatic website transfers; this can prevent some real sites from functioning and needs explicit compatibility follow-up. Transfer integration, saved annotations/style feedback, developer diagnostics/full-CDP equivalents, durable protected browser sign-ins and regular-browser extension integration remain separately recorded until implemented or explicitly scoped by the user.
