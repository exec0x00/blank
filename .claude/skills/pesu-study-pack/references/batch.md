# Batch protocol: one subject-unit per session

Used when many packs are built in parallel cloud sessions, each owning **one subject-unit** (e.g. Engineering
Chemistry Unit 2). Each session starts from the branch that holds this skill and pushes to its own branch;
the orchestrator merges the branches, so **stay inside your own directories**.

## What you own

- `packs/<subj>-u<N>-<NNN>-<slug>/`: one pack per class session (NNN = the bucket's session number). When the bucket
  splits one class across two numbers (or a session folder only repeats another), you may combine them into one pack
  named after both numbers (e.g. `…-u1-013-014-experiential`). Say why in its `coverage_note`.
- `packs/<subj>-u<N>-unit-master/`: generated by `scripts/merge_unit.py` from your session packs, in teaching order.
- `packs/_shared/<subj>/`: subject-wide downloads (CW sheets, ESA papers, consolidated slides) plus `esa_map.md`, which
  maps every past-paper question of your unit to a session. It is git-ignored except `esa_map.md`.
- `packs/_notes/<subj>-u<N>.md`: your report. Include sessions, page counts, gaps, conflicts, ESA coverage and new lessons.

**Never edit** anything under `.claude/` (the skill, engine, workflows) or another session's packs. If the engine needs a
fix, work around it in your pack content and describe the fix in your notes file; the orchestrator applies it once.

`<subj>` short names: `maths`, `chem`, `ec` (Electronic Principles and Devices), `mech` (Engineering Mechanics),
`python` (Python for Computational Problem Solving), `law` (Constitutional, Cyber, IP Law and Professional Ethics).

## Steps

1. `bash .claude/skills/pesu-study-pack/scripts/setup.sh`. Read `SKILL.md`, `references/*` (lessons first) and the
   example pack. Use the repo copy of the skill (`.claude/skills/pesu-study-pack`) as `SKILL_DIR`.
2. **Subject scout (once):**
   - List your unit's sessions in the bucket.
   - Download the subject's `First_Year_8enterprise` CW sheets, ESA papers and consolidated slides into
     `packs/_shared/<subj>/` (password `8enterprise`).
   - Render the papers and map every question of your unit to a session in `esa_map.md`: paper, question, marks,
     exact text, session.
3. **Session packs:** one pack per session, following SKILL.md steps 1–7 completely:
   - Read the rendered slides as images, all transcripts and the papers.
   - Verify every number with sympy, or by running your own code for programming subjects.
   - Redraw every figure, and do the visual QA of every figure and page sheet.
   - QA must pass. Never commit a pack whose QA fails.

   Use the Agent tool to build several session packs in parallel, about 3 at a time. Give each agent this file, its
   session, its pack directory, the `esa_map.md` lines for its session, and the instruction to return a short report:
   pages, gaps, ESA questions, lessons.
4. **Unit master:** after all session packs pass, run
   `python3 -I .claude/skills/pesu-study-pack/scripts/merge_unit.py packs/<subj>-u<N>-unit-master --title "<Subject> — Unit <N> Master" --unit "<unit name>" --slug <subj>_unit<N> --header "<short subject> · Unit <N> · Master" <session packs in teaching order>`.
   Then run `make.sh … --sheets`, look at the sheets, and fix the session packs (not the generated files) if anything is
   wrong, then re-merge.
5. **Commit and push** to your branch:
   - commit `pack.py`, `parts/`, `figures.py`/`figs/`, `output/*.pdf` and `output/standalone/*.html`;
   - add `output/assets/` and `output/*.html` to each pack's `.gitignore` to keep the repo small;
   - commit `packs/_shared/<subj>/esa_map.md` and your notes file.

   Commit after each pack passes, not only at the end, so progress survives a container restart.

## Subject notes

- **Maths / Mechanics / Chemistry / Electronics:** numerical. Verify every worked answer with sympy (lesson 14). Circuits,
  free-body diagrams, phase diagrams and spectra must be redrawn with `figstyle` (matplotlib); schematic diagrams can be
  drawn with matplotlib patches and lines.
- **Python:** use `code` instead of `tex` for formulas (content-schema). Run every code example yourself, in a scratch
  directory, with your own copy of the code, and quote the real output. Never execute downloaded files. Flowcharts
  suit control flow; comparison tables suit data types and operators.
- **Law and ethics:** no numericals. Formulas become key provisions (article numbers, definitions, landmark cases)
  quoted from the slides. Figures may be timelines and structure diagrams (Union/State organs, the hierarchy of courts).
  Never invent article numbers or case names: only what the slides or transcripts say, flagged otherwise.
